## Decisions
- Preserve F03 scale 6 / HALF_UP; stored utilities must already be exact at 6 places. Convert using longValueExact. Divide all integers by their positive GCD (1 for all zero). This is lossless and permits normal currency values while respecting actual SPMF int32 totals. Reject a normalized dataset total above Integer.MAX_VALUE. Mapping: Products sorted ascending, dense IDs 1..N. No utility fabricated and no negative row discarded.
- Percentage threshold = ceil(percent * normalizedTotal / 100), percent (0,100]. Absolute threshold is in original weighted utility units (at most 6 decimal places), converted using ceil(value * 10^6 / gcd). Require positive int32 threshold. Percentage of all-zero data is invalid; positive absolute threshold over all-zero data gives a valid empty result.
- Use existing four ERD tables. Store an immutable internal input and mapping in MINING_REQUEST plus original snapshot metadata. This deliberately duplicates execution input, not configuration ownership. Database constraints scope snapshot/request/run/Product relations by Store.
- POST returns 202 and persisted IDs; client UUID requestKey is unique per Store and idempotent for identical payload, 409 for changed payload. Single-process MVP with one worker/queue capacity 8; no clustered worker guarantee. Startup marks unfinished jobs FAILED/INTERRUPTED, never silently resumes. Retry uses a new requestKey and creates a new audited request.
- Pattern batch persistence and COMPLETED status share one transaction. Parser validates canonical keys, known IDs, threshold, exact utility recomputed only by summing frozen input values for that itemset (never recalculates F03 Weight), output limits and duplicates. Support omitted/null because SPMF output does not measure it.
- Sequential algorithm runs use the same bytes, mapping, absolute threshold, heap and executable. Wall runtime includes child JVM startup and mining/file IO, excludes common input preparation; memory is SPMF sampled Java heap MiB, never RSS. No warmup, one cold execution each; no general performance winner claim. Exact itemset+integer-utility mismatch is FAILED comparison.
- Existing snapshots' matrixHash was generated by version-specific JSON. Preserve it as provenance; do not regenerate using newer DTOs and reject valid historical JSON. Validate stored weighted total and transaction totals, IDs, Store, status, scale and source/matrix hash shapes; pin a new execution input hash. Does not claim cryptographic reauthentication of legacy snapshots.
