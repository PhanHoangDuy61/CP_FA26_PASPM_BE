# F05 Scheduler — acceptance matrix, 2026-11-01

Current decision: **Scheduler NOT_READY; activation HTTP 503 retained; branch NOT_READY.** The original crash-point tests below used image `ea81feeff192`; the later final-gap tests used instrumented image `4366b539a5ea`. Both used synthetic records in disposable MySQL 8.4.13, actual Backend containers, Java 17 and hash-verified SPMF/Java 25. Host is macOS ARM using Linux/amd64 Docker emulation. The public enable API was not bypassed in the application; enabled schedules used by internal acceptance were seeded directly only in the disposable DB. Details and IDs: [crash evidence](../testing/evidence/F05_SCHEDULER_CRASH_ACCEPTANCE_2026-11-01.txt).

| Acceptance case | Result | Evidence and qualification |

| Crash before reservation commit | PASS | MySQL trigger/named-lock barrier; A killed; no committed occurrence/snapshot; B completed exactly one occurrence/request. |

| Concurrent schedule polling | PASS | Two actual containers contended on the same schedule; MySQL data-lock wait observed. Exactly one occurrence, snapshot and request; two completed runs, MATCH. |
| Occurrence retry and finalization | PASS | SPMF missing-runtime and SQLSTATE 40001 test injections persisted retry then completed at attempt 2; FAILED-request reconciliation was observed. Final-image tests observed 15/30-second delays and terminal third attempt, plus successful recovery after restart during backoff, without changing timestamps. | MySQL TCP disconnect/reconnect | PASS | Test proxy forcibly dropped 20 live TCP connections and rejected reconnects while workers were active; all four requests, including a newly due schedule, completed after proxy restoration without editing lease timestamps. The MySQL server itself was not restarted. |
| Approved scheduling policies | BLOCKED | Product Owner has explicitly requested that 503 remain. [Detailed policy proposals](F05_SCHEDULER_POLICY_DECISIONS.md) are awaiting approval. |

Additional unresolved acceptance: database server restart and extended network partition beyond the test proxy disconnection; schedule changes after the mining request has already started executing (preparation-time updates were tested); additional occurrence-lease expiry and clock-change edge cases; production observability/alerting policy for DEBUG queue rejection and a launcher indefinitely stopped before parent-death registration; immutable snapshot and mining-output provenance across every required crash case. No merge or deployment has been authorized.

A final-image two-container worker lease-loss experiment stopped a real SPMF child, revoked the worker owner/fence, observed child cleanup and recovered the same request on B with fence 3; worker expiry was advanced in the disposable DB. See [evidence](../testing/evidence/F05_SCHEDULER_CRASH_ACCEPTANCE_2026-11-01.txt).

Final-gap results: actual TCP connections to disposable MySQL were forcibly dropped and restored while worker/scheduler requests were active; four requests completed with no lease timestamp edits, and two worker fences advanced to 2. Both final-image containers also started simultaneously against an empty schema and recovered a PENDING request/due schedule after simultaneous restart. Real Java SPMF children in two containers survived independently: killing Backend A removed A child while B child remained active, then both requests completed. A test-only launcher wrapper additionally held startup before `prctl`; after A died it was released, exited without starting SPMF and the same request recovered with fence 2. See [final gap evidence](../testing/evidence/F05_FINAL_GAPS_2026-11-01.txt). These tests do not constitute PO approval or remove 503.
