1. Only the F03/F05-relevant pages were reviewed for UML 2.0 semantics. The remaining pages (F01, F02, F04, F06, planned A/B, storefront, screen flow) were not audited here.
2. R2-04 remains a layered block diagram annotated with component keywords, not a full UML component diagram with provided/required interfaces and ports; and there is **no UML deployment diagram** (Linux Docker, Java 17 backend + Java 25 SPMF child, MySQL 8.4). Adding one would add a 28th page; this was not done because the page count and ids were to be preserved. Recommended after approval.
3. No state diagram for the schedule occurrence (`PENDING`, `PROCESSING`, `DISPATCHED`, `COMPLETED`, `FAILED`; attempts 3, delays 15 s then 30 s). Not added: decisions D6/D8 may change the states (for example a skipped state), so drawing it now would document an unapproved policy.
4. AD03 does not model the worker lease/heartbeat as a loop or a fork/join: runs are sequential, so no fork/join is justified.
5. The corrected file must be committed on a diagram branch (a new branch from `3e369f0` is suggested so the existing `3e369f0` stays untouched) before it can enter a pull request; that needs your authorization.
